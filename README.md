# Milestone 1 — Schema & Data Load

This folder contains the database schema and a script to populate the project's SQLite database using the CSV files in the repository `data/` folder.

Quick start (macOS / zsh):

1. Make sure you have Python 3 installed (3.8+ recommended).

2. Run the loader script from the repository root:

```bash
python3 milestone1_schema/load_data.py
```

- The script will execute `milestone1_schema/schema.sql` and then import CSVs into `database.db` at the repository root.
- If `database.db` exists it will be opened and tables will be created/overwritten where appropriate (INSERT OR REPLACE).

Notes:
- The loader uses only the Python standard library (`csv`, `sqlite3`) so no extra packages are required.
- For large CSVs the script batches inserts to reduce memory usage.
- If you prefer PostgreSQL or MySQL, the `schema.sql` is a good starting point but you'll need to adapt types and the loader (e.g., use `psycopg2` or `mysqlclient`).

# Milestone 2 — Data Ingestion

## 1. Project Overview

The Career Intelligence and Job Analytics Platform is a relational database system that assists users in making informed career decisions. It provides:

- **Best Fit Jobs** — roles that closely match a user's current skills
- **Growth Jobs** — roles that expose skill gaps, supporting long-term development
- **Market Analytics** — skill demand trends, salary distributions, and career progression insights

The database spans three domains: User Profile, Job Market, and Analytics.

## 4. Data Dictionary

### `skills`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `skill_id` | INTEGER | Primary key | 1–35 |
| `skill_name` | TEXT | Full skill name | e.g. "Information Technology" |
| `category` | TEXT | Skill grouping | Technology, Finance, Analytics, Marketing, Human Resources, Creative, Management, Operations, General |

### `companies`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `company_id` | INTEGER | Primary key | 1–3000 |
| `company_name` | TEXT | Company name (unique) | Any string |
| `industry` | TEXT | Industry sector | e.g. "IT Services and IT Consulting" |
| `size_range` | TEXT | Headcount band | 1-10, 11-50, 51-200, 201-500, 501-1000, 1000+ |
| `hq_location` | TEXT | City, state, country | Free text |

### `job_listings`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `job_id` | INTEGER | Primary key | 1–10000 |
| `company_id` | INTEGER | FK → companies | Valid company_id |
| `title` | TEXT | Job title | Free text |
| `location` | TEXT | Job location | City, State format |
| `salary_min` | REAL | Min salary in USD | ≥ 0, NULL if undisclosed |
| `salary_max` | REAL | Max salary in USD | ≥ salary_min, NULL if undisclosed |
| `employment_type` | TEXT | Contract type | Full-time, Part-time, Contract, Internship |
| `description` | TEXT | Job description (truncated 500 chars) | Free text |
| `posted_date` | TEXT | Listing date | YYYY-MM-DD |
| `is_active` | TEXT | Whether listing is open | true / false |

### `job_skills`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `job_skill_id` | INTEGER | Primary key | Sequential |
| `job_id` | INTEGER | FK → job_listings | Valid job_id |
| `skill_id` | INTEGER | FK → skills | Valid skill_id |
| `requirement_level` | TEXT | How essential the skill is | Required, Preferred, Nice-to-have |

### `users`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `user_id` | INTEGER | Primary key | 1–1470 |
| `full_name` | TEXT | Anonymised name (IBM source) | e.g. "Female Employee 1" |
| `email` | TEXT | Platform email (unique) | emp{N}@careerplatform.com |
| `location` | TEXT | City, country | New York US / San Francisco US / Chicago US |
| `years_experience` | INTEGER | Total working years | 0–40 |
| `created_at` | TEXT | Account creation timestamp | YYYY-MM-DD HH:MM:SS |

> **Note on names:** The IBM HR Attrition dataset anonymises all personal identifiers by design. Names are derived from gender and employee number to satisfy schema requirements while respecting the source data's privacy intent.

### `education`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `education_id` | INTEGER | Primary key | Sequential |
| `user_id` | INTEGER | FK → users | Valid user_id |
| `institution` | TEXT | University name | e.g. "University of California" |
| `degree` | TEXT | Degree level | High School Diploma, Associate's Degree, Bachelor's Degree, Master's Degree, Doctoral Degree |
| `field_of_study` | TEXT | Academic field | e.g. "Life Sciences", "Marketing" |
| `graduation_year` | INTEGER | Year of graduation | 1950–2100 |

### `user_skills`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `user_skill_id` | INTEGER | Primary key | Sequential |
| `user_id` | INTEGER | FK → users | Valid user_id |
| `skill_id` | INTEGER | FK → skills | Valid skill_id |
| `proficiency_level` | TEXT | Skill level | Beginner, Intermediate, Advanced, Expert |
| `acquired_date` | TEXT | Estimated acquisition date | YYYY-MM-DD |

> Proficiency is derived from `TotalWorkingYears` in the source: ≤2 yrs = Beginner, ≤6 = Intermediate, ≤12 = Advanced, >12 = Expert.

### `market_trends`
| Column | Type | Description | Allowed Values |
|---|---|---|---|
| `trend_id` | INTEGER | Primary key | Sequential |
| `skill_id` | INTEGER | FK → skills | Valid skill_id |
| `recorded_month` | TEXT | First day of the year (YYYY-01-01) | 2020–2024 |
| `demand_score` | INTEGER | Normalised demand index | 0–100 |
| `avg_salary` | REAL | Average USD salary for this skill/year | ≥ 0 |
| `trend_direction` | TEXT | Direction vs prior year | Rising, Stable, Declining |

## 5. Setup and Import Instructions

### Prerequisites

- Python 3.8+ (standard library only — no pip installs needed)
- SQLite is bundled with Python — no separate installation required

### Step 1 — Clone or download the repository

```bash
git clone <your-repo-url>
cd DBMS_PROJECT
```

### Step 2 — Load all data into SQLite

Run this single command from the repository root:

```bash
python3 milestone1_schema/load_data.py
```

This will:
1. Create `database.db` at the repository root
2. Execute `milestone1_schema/schema.sql` to create all 8 tables and indexes
3. Import all 8 CSV files from `data/` in the correct foreign-key order

Expected output:
```
Connecting to SQLite DB: .../database.db
Applying schema from .../schema.sql
Loading users.csv -> users       loaded 1470 rows
Loading companies.csv -> companies   loaded 3000 rows
...
All done. Database populated at: .../database.db
```

### Step 3 — Verify the data loaded

```bash
python3 -c "
import sqlite3
conn = sqlite3.connect('database.db')
tables = ['skills','companies','job_listings','job_skills','users','education','user_skills','market_trends']
for t in tables:
    n = conn.execute(f'SELECT COUNT(*) FROM {t}').fetchone()[0]
    print(f'{t:<22} {n:>6} rows')
conn.close()
"
```

### PostgreSQL alternative

If using PostgreSQL instead of SQLite:

```bash
# Create database
psql -U postgres -c "CREATE DATABASE career_intelligence;"

# Run schema
psql -U postgres -d career_intelligence -f milestone1_schema/schema_postgres.sql

# Import CSVs (run from repo root)
psql -U postgres -d career_intelligence -c "\COPY skills        FROM 'data/skills.csv'        CSV HEADER;"
psql -U postgres -d career_intelligence -c "\COPY companies     FROM 'data/companies.csv'     CSV HEADER;"
psql -U postgres -d career_intelligence -c "\COPY users         FROM 'data/users.csv'         CSV HEADER;"
psql -U postgres -d career_intelligence -c "\COPY job_listings  FROM 'data/job_listings.csv'  CSV HEADER;"
psql -U postgres -d career_intelligence -c "\COPY job_skills    FROM 'data/job_skills.csv'    CSV HEADER;"
psql -U postgres -d career_intelligence -c "\COPY education     FROM 'data/education.csv'     CSV HEADER;"
psql -U postgres -d career_intelligence -c "\COPY user_skills   FROM 'data/user_skills.csv'   CSV HEADER;"
psql -U postgres -d career_intelligence -c "\COPY market_trends FROM 'data/market_trends.csv' CSV HEADER;"
```

## 6. Running the Queries

Open `milestone2_sqlqueries/queries.sql` in any SQLite client (DB Browser for SQLite, DBeaver, or the `sqlite3` CLI):

```bash
sqlite3 database.db < milestone2_sqlqueries/queries.sql
```

Or interactively:
```bash
sqlite3 database.db
sqlite> .read milestone2_sqlqueries/queries.sql
```

Each query is labelled Q01–Q12 with a comment explaining its business purpose.

**Query coverage:**

| Query | Type | Purpose |
|---|---|---|
| Q01 | Aggregation | Avg salary by employment type |
| Q02 | Aggregation | Top 15 most demanded skills |
| Q03 | 3-table Join | Active job listings with company details |
| Q04 | 4-table Join | Full user skill and education profile |
| Q05 | Correlated Subquery | Best Fit Jobs for a user |
| Q06 | Scalar Subquery | Companies paying above average |
| Q07 | CTE | Skill gap analysis for a user |
| Q08 | Chained CTEs | Year-on-year salary growth per skill |
| Q09 | Window RANK | Jobs ranked by salary within company |
| Q10 | Window SUM + ROW_NUMBER | Running total of listings by month |
| Q11 | CTE + Window (bonus) | Personalised job recommendation |
| Q12 | Mixed aggregation (bonus) | Market intelligence by skill category |

## 7. Running the Recommender

```bash
# Recommend top 10 jobs for user_id 1
python3 milestone2_sqlqueries/recommender.py --user 1

# Recommend top 5 jobs for user_id 42
python3 milestone2_sqlqueries/recommender.py --user 42 --limit 5

# Custom weights
python3 milestone2_sqlqueries/recommender.py --user 1 --location-bonus 0.8 --half-life 3.0
```

The recommender scores jobs using weighted skill overlap, location match, and company growth signal. It reads from `database.db` — run `load_data.py` first.

## 9. Data Cleaning Notes

- **job_listings:** Filtered from 123,849 raw postings to 10,000 matching companies in our company table. Salary values under 5 treated as NULL (hourly micro-values). Unix millisecond timestamps converted to YYYY-MM-DD.
- **companies:** Filtered from 24,473 to 3,000 companies that appear in job postings.
- **job_skills:** Filtered from 213,768 to 16,750 rows where both job_id and skill_abr exist in final tables.
- **users:** 1,470 IBM HR records used as-is. Names anonymised in source dataset.
- **education:** Education level codes (1–5) mapped to degree names. Field of study from `EducationField` column.
- **user_skills:** JobRole mapped to relevant skill abbreviations. Proficiency derived from `TotalWorkingYears`.
- **market_trends:** 5,736 salary records aggregated by (skill, year) to produce 29 annual snapshots (2020–2024).
